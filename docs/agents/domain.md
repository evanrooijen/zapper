# Domain docs

This repo uses a single-context layout:
- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If they are absent, proceed silently. The domain-modeling skill creates
them lazily as terms and decisions are resolved.

Use the glossary's vocabulary in issues, proposals, hypotheses, and tests.
If a term is missing, reconsider the wording or note the gap for
domain-modeling.

Explicitly flag proposals that contradict an existing ADR, identifying
the ADR and explaining why its decision should be reconsidered.
